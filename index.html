AP Invoice Exception and Reconciliation Pipeline

Python, PostgreSQL, HTML dashboard. Personal project, synthetic data only.

An accounts payable exception engine. It reads invoice documents written the way OCR actually outputs them (Rs. 13,125.00, GST @5% 625.00, three different date formats) and applies four financial controls to every record: tax rate mismatch, duplicate invoice from the same vendor, missing PO reference, and invalid amount. Every failure is written to an exception log with the required action, so one bad row cannot hide a second problem behind it.

Outputs a reconciled batch file, an exception queue with severity and required action, an audit summary by control, and a self-contained HTML control dashboard for the reviewer.

Automated Financial Invoice Extractor

Gemini 2.5 Flash vision, Pydantic v2, Pandas, Excel export. Personal project, synthetic data only.

Document-to-data pipeline for invoice images and PDFs. Instead of fragile OCR regex, the model reads the document and must return a strict typed schema: vendor, invoice number, date, line items, subtotal, tax, total. The pipeline then re-does the arithmetic itself, verifying that line items sum to the subtotal and subtotal plus tax equals the total, and flags any document that fails before it reaches a ledger.

2independent reconciliation checks
1validated multi-sheet Excel ledger
PASS / FLAGGEDstatus per document

Built around a simple premise: an extraction pipeline in finance is only as good as its ability to refuse bad data. Schema validation catches malformed output, and the arithmetic check catches documents that are internally inconsistent.
